# AANodeGroups

AANodeGroups 为 AzureArchive 剧情编辑器提供节点分组功能，便于整理节点、观察连线并节省画布空间。Mod 的安装名称为 **NodeGroups**，当前版本为 **1.0.3**。

## 功能介绍

- 将多个节点收进同一个组，支持编辑组名、展开和折叠。
- 使用原生节点风格的单个“创建组”按钮，支持直接拖动按钮调整位置。
- 拖动组标题移动整组；在左、左下、下、右下、右五处调整展开区域。
- 通过拖拽将节点加入、移出或转移到其他组，支持多选节点一起拖动。
- 从原生下方菜单创建节点时，可直接拖放到目标组。
- 回收站内的节点不计入组显示数量；原生撤销可恢复，拖回画布时按最终落点确定归属。
- 组卡片、字体和外部白色连线复用原生样式；黄色表示选中，绿色表示拖放目标，绿色优先。
- 支持原生 Undo/Redo，组信息随工程侧车文件保存。
- 分组改动会点亮原生保存按钮，空组同样适用；离开编辑器或关闭应用时提醒尚未保存的分组。

节点组是编辑器视图中的整理工具。真实节点、连接、剧情预览与编译仍由 AzureArchive 管理，组信息单独保存。

## 安装与启用

需要已配置 BepInEx 6 IL2CPP 的 Windows 版 AzureArchive 环境。目前支持AzureArchive 1.0.0 和 1.0.1版本。

1. 准备发行版 `NodeGroups.dll`、`manifest.json` 和 `icon.png`，关闭 AzureArchive。
2. 将三个文件放入应用目录下的 `mods/NodeGroups/1.0.3/`：

   ```text
   AzureArchive/
   └─ mods/
      └─ NodeGroups/
         └─ 1.0.3/
            ├─ NodeGroups.dll
            ├─ icon.png
            └─ manifest.json
   ```

3. 在应用的 Mod 管理界面启用 `NodeGroups/1.0.3`，然后重启应用。

同一 Profile 只启用一个 NodeGroups 版本。清单版本与安装目录应一致，更新版本时先关闭应用。需要禁用时，在 Mod 管理界面关闭 NodeGroups 并重启；原工程中的真实节点会继续保留。

源码编译和开发环境配置见 [开发与测试指南](DEVELOPMENT.md)。

## 使用方法

进入剧情编辑器后，画布左上侧提供一个“创建组”按钮，采用原生节点的白色圆角背景和蓝色字体。直接拖动按钮可以调整位置，画布平移或缩放不会带动按钮。拖动结束不会创建组。

| 操作 | 使用方法 |
| --- | --- |
| 创建组 | 按原生方式选择节点，点击“创建组”或按 `Ctrl+G`；未选择节点时创建空组。 |
| 选中组 | 点击标题、折叠卡片或边框；边框变黄，选中组提升到其他组上方。 |
| 修改名称 | 双击组标题；`Enter` 或点击其他位置确认，`Escape` 取消。编辑时显示黑色插入光标，名称最多 256 字符。 |
| 折叠或展开 | 点击标题上的“折叠”或“展开”；折叠卡片显示名称和成员数量。 |
| 移动整组 | 拖动上边框或标题空白处；组内节点一起移动并保持相对布局。 |
| 调整区域 | 拖动左边、右边、下边或两个底角；光标提示缩放方向，上边框只用于移动。 |
| 加入、移出和转移节点 | 拖动节点，松手时确定归属；拖到组外即移出，拖入其他组即转移。 |
| 新建节点入组 | 从原生下方菜单拖入目标组，原生节点创建成功后加入。 |
| 回收与取回节点 | 拖入原生回收站后减少组显示数量；撤回则恢复原组，拖回画布则按松手位置确定归属。 |
| 拖入折叠组 | 在折叠卡片上松手，目标组自动展开并加入节点。 |
| 解散组 | 点击标题上的“解散”；成员节点和连接保留，撤回可恢复组。 |
| 撤销和重做 | 使用原生 撤销/重做 按钮或快捷键。 |
| 保存组信息 | 使用原生保存操作或 `Ctrl+S`，分组信息随工程保存。 |

原生节点或已提交的分组信息有未保存改动时，原生保存按钮会亮起。空组的创建、重命名、移动、缩放、折叠与解散也会计入；撤销回保存点后，若原生工程也没有其他修改，按钮恢复原状态。分组文件写入失败或保存期间又有修改时，仍保留未保存提示。尚可取消的拖动或缩放预览不计入已提交分组，也不会作为分组内容保存。

返回或退出编辑器时，未保存分组会触发原生退出确认。关闭整个应用时同样会进行检查：选择“取消”后可使用原生保存按钮或 `Ctrl+S` 保存，选择“仍然退出”则继续关闭。已打开其他窗口或正在编辑、拖动时，请先完成当前操作再关闭。

有效拖放目标的边框会变绿，即使该组已经选中也优先显示绿色；离开或结束拖放后恢复原色。悬浮提示不改变成员数量、选中组或层序。

多个组重叠时，优先操作顶层组；只有选中组才改变层序。展开组的标题区域不用于入组，目标判断使用拖动主节点的主体中心。

调整边框只改变组区域，不移动或缩放节点，也不自动增减成员。边框不能缩小到排除现有成员；移出成员需要拖动节点。组内不可见节点需先展开才能拖出，空组仍会保留。

组显示数量只统计当前仍在画布上注册的成员，折叠隐藏的成员仍计入。节点进入原生回收站后数量减少，原归属暂时保留用于撤销；一次 Undo 会恢复回收前的位置、归属和数量。将节点从回收站拖回原组会恢复计数，拖入其他组会转移归属，拖到组外则清除原归属；取消取回时保持回收站状态和组信息不变。回收站的暂存、恢复及节点生命周期仍由 AzureArchive 管理。AzureArchive 1.0.1 不支持批量回收，请逐个拖入回收站。

## 保存、备份与恢复

组信息保存在剧情工程旁，文件名包含工程的完整扩展名，例如：

```text
序章.aap2
序章.aap2.nodegroups.json
```

备份、移动或分享工程时，请同时保留这两个文件。组文件记录名称、成员 GUID、折叠状态、组锚点、展开区域和层序；节点位置、连接及剧情以原工程为准。

组文件损坏、工程身份不匹配或无法读取时，Mod 会记录诊断并保护原文件，避免用空分组覆盖。请先备份，再修复或移走组文件并重新打开工程。诊断可在应用的 `BepInEx/LogOutput.log` 中查看。

退出时，未保存的组信息会尽力写入应用目录下的 `ModDev/NodeGroups/artifacts/recovery/`。打开工程并检测到较新的恢复副本时，会显示原生恢复确认框；选择“恢复”导入组信息，之后使用原生保存操作或 `Ctrl+S` 保存。选择“暂不恢复”或关闭提示不会导入数据、不会删除恢复副本，本次会话内也不会重复提示；重新打开工程后可再次选择。

恢复可以撤销。恢复副本只保存组元数据，不恢复未保存的台词、节点创建或移动。

每份工程最多保存 1024 个组、每组 10000 个成员、全部组共 50000 个成员；暂时回收或缺失、保留归属供撤销恢复的成员仍占用容量，但不计入组显示数量。达到容量后拒绝新增组或入组，仍可移出成员或解散组。从菜单创建的节点若因容量无法入组，保留原生创建结果并留在组外。组锚点和边框限制在画布坐标 ±10000000 内，组文件大小上限为 8 MiB。

## 声明与适用范围

- 本项目提供 AzureArchive 编辑器扩展功能，不附带原应用、Unity/BepInEx 二进制、互操作程序集或游戏资源。相关软件与资源按其各自许可使用。
- 当前已在 Windows 版 AzureArchive 1.0.1、BepInEx 6 IL2CPP 环境验证。应用后续更新仍需重新验证适配性。
- 每个节点只能属于一个组，暂不支持嵌套组。折叠后的代理连线用于观察，创建、修改或剪断连接前请先展开相关组。
- 使用和更新 Mod 前，请备份原工程及同名组文件。恢复副本不能替代完整工程备份。
